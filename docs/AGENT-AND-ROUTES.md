# Agent 收件箱与设备传输线路

在设置的 **MCP** 中启用 MCP 访问。可关闭「允许读取附件内容」以保留已授权的消息和文件列表。然后，复制 MCP 配置到支持 stdio 的客户端。配置使用本机 Node.js（推荐 Node 24 LTS，含 node:sqlite）。安装版和便携版请使用设置页生成的配置，其中包含本机实际脚本和数据库路径。

收件默认不共享。在已接收的卡片上右键可授权单项；在设备详情授权后，新收到且客户端证书与发送设备身份匹配的记录自动可读。关闭总开关或撤销授权后，下一次读取立即生效。单条授权和设备授权独立生效。授权无法收回已返回的内容。只读服务从本机数据库查询，不监听网络。文本/图片附件的单次读取上限为 8 MiB；不执行附件。

设备会话顶部的「传输线路」按设备保存。系统识别相应网络接口后可选择 Wi-Fi、以太网或 USB4/雷电网络。接口说明报告代际时显示规格；网卡协商速率和带宽测速是不同指标。自动线路按近期上传测速、网卡发送速率排序，存在多个候选时发送前验证；手动线路离线时可重新选择自动再重试。切换线路作用于后续任务。

双机验收：保持原有局域网连接，在独立子网上增加有线或 USB4 网络。两端分别打开同一设备详情，逐线路选择、测速并传同一个大文件，交换发送方向，核对任务线路和文件 SHA-256；传输期间拔线验证中断与重试。USB4 实机测试要求两端系统实际枚举出互联网络适配器。仅有雷电控制器或普通 USB-C 接头不代表已成功联网。

## 发送端搜索

会话输入区的放大镜按文件名搜索，勾选结果后点击「确认发送」，发送至当前设备。在「设置 → Everything」选择搜索文件夹。Windows x64 优先通过随附的 voidtools ES 客户端访问本机正在运行的 Everything（先查询 1.5a 实例，再查询默认实例）。Windows x64 未检测到可查询的 Everything 实例时，首次搜索会启动随包提供的 Everything 1.5 Beta，在用户数据目录 search-index 中维护独立索引。索引尚未返回有效结果时使用目录扫描。每次最多展示 50 项，达到扫描预算时显示部分结果。接收设备无需安装 Everything。

MCP 客户端可调用 `search_local_files`、`list_send_devices` 和 `send_local_file`。发送端须运行 LocalLink，同时开启 MCP 访问，并在「本机文件搜索」中允许相应范围。发送目标须在线且已配对。默认逐次确认；在设备详情中可授权从当前搜索目录向这台设备自动发送。更换搜索目录后原规则不适用于新目录。
