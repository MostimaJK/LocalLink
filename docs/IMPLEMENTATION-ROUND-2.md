# LocalLink 第二轮：传输、记录与桌面交付

日期：2026-11-21；审查基线：`5955410`。本轮按同一份清单推进多个方向，并完成 Windows 可运行增量。下表区分实现、验证和仍未完成的工作，不能把“全部开始”理解为所有平台和增强协议已经完成。

## 已实现

| 方向 | 当前行为 |
| --- | --- |
| 备份可靠性 | 补齐消息/通话恢复的 call 参数；事务失败保留原记录。旧 JSON 传输记录自动迁入独立 SQLite 表。旧 ZIP 备份直接解析 backup.json 并校验 CRC，不再执行 shell 解压；适配 archiver 8 的 ESM API。 |
| 传输生命周期 | 接收确认后建立稳定任务 ID；排队、准备、等待接收、传输、等待确认/校验、完成、失败、取消均有记录。持续有数据时刷新闲置期限，不再固定十分钟中断活跃上传。 |
| 进度与控制 | 文件卡片展示流中实际读取/接收字节和平均速率。字节读完后等待 HTTP 确认，之后才显示已送达。支持取消当前批次、失败重新发送；重试生成独立记录，原失败记录保留。 |
| 批量文件 | 原生选择器支持多选；一批最多 100 个文件、总计 500 MiB，一次接收确认，顺序发送。可拖入文件。文件夹递归发送未实现。 |
| 聊天式输入 | 保留左右时间线，加入文本/链接输入、Ctrl/Cmd+Enter、草稿保留、复制文本、粘贴图片、图片缩略图。文本通过 text/plain 文件与 preview 传输，限制 64 KiB；图片粘贴限制 32 MiB。缩略图独立生成，文件流不转换原字节。 |
| 手动发现 | 默认模式的“连接设备”使用 LocalSend register；支持 IP、端口、显式 http/https。HTTPS 首次身份取自证书，后续发送校验指纹。手动发现仍不授予信任。 |
| 协议响应 | 识别 204 已结束、401 PIN、403 拒收、409 忙、422 校验失败等；401 的失败卡片重试时可输入 PIN。未声称通过原版客户端全部兼容测试。 |
| 接收与磁盘 | 可以选择和打开接收目录，校验可写性，接收前检查可用空间；已开始的会话保留原目录，新会话使用新目录。磁盘/目录异常进入失败记录。 |
| 记录与性能 | 独立索引表逐条更新；会话与全部记录每页 100 条，支持前后翻页、文件名搜索、收发方向筛选。进度变化局部刷新卡片；保留阅读位置和输入草稿。 |
| 文件备份 | 新传输备份支持仅记录、记录加原文件；导出为独立文件夹及 locallink-backup.json。导入校验 SHA-256、重建路径并保留文件名；不迁移证书或设备身份。缺失原文件会报告数量；仅记录备份不伪造可用文件路径。 |
| 界面收敛 | 默认模式的历史入口统一使用新记录；隐藏重复活动中心入口，无旧群组时隐藏群组页签。通知设置只保留传输结果开关；进阶页改为实际端口/IP/服务状态和重试。旧连接和旧历史代码保留。 |
| 品牌与启动 | Windows 文件名、产品元数据和应用图标使用 LocalLink；默认数据目录明确保持原有 orbit-beta，显式 --user-data-dir 仍优先。上游许可证继续包含在分发文件中。 |
| 依赖 | 更新 desktop 的 sharp 至 0.35.5、Capacitor 至 8.6.2 及若干间接依赖；移除源码未引用的 sqlite3，保留实际使用的 better-sqlite3。mobile 独立工程依赖没有随之自动升级。 |

## 运行与构建

- 开发运行：项目根目录 `Start-LocalLink.bat`。已在运行的旧进程需从托盘退出后重新启动。
- 本地 Windows 构建：在 desktop 执行 `npm run build:win:local`，使用已按 Electron ABI 安装的原生模块。构建脚本所用 rcedit 需要 Node >= 22.12；本机 Node 24.19 验证。
- 生成入口：`desktop/dist/win-unpacked/LocalLink.exe`。这是未签名的完整目录构建，必须保留旁边的 resources 和 DLL，不能只复制 exe。
- 构建绕过 electron-builder 的 winCodeSign 跨平台压缩包解压步骤，使用 npm 随附的 rcedit 修改本地 Windows 资源；没有修改系统开发者模式/权限或发布任何产物。
- NSIS 安装、卸载、升级迁移、签名及自动更新仍未验收。内部 appId、SQLite 文件名和原协议标识保留。

## 验证证据

- `tests/localsend-protocol.test.js`：本机独立 HTTPS 两端字节一致、真实确认、拒收、错误 token、错误哈希失败记录、TLS 指纹不匹配、危险文件名。
- `tests/localsend-tasks.test.js`：手动 HTTPS register、多文件、零字节、接收完整生命周期、慢速连续上传超过缩短后的闲置期限仍成功、过期任务失败记录、接收/等待确认时取消、PIN 和 204 响应。PIN/204 用受控测试端模拟，不等于原版客户端验收。
- `tests/transfer-storage.test.js`：旧 JSON 迁移、带特殊字符的搜索、普通消息/通话/文件元数据的 ORZIP/ZIP 往返恢复、旧版本恢复和事务回滚。
- `tests/transfer-archive.test.js`：原文件导出/导入、路径重建、损坏文件与路径穿越拒绝、仅记录恢复、万条记录分页。一次本机内存 SQLite 测量：插入 10,000 条约 53 ms，读取偏移 9,000 的 100 条约 1 ms；这不是磁盘长期负载基准。
- `tests/localsend-large-file.test.js`：500 MiB 本机回环传输约 3.1 秒；两个端点共用一个 Node 24 测试进程，RSS 基线 63 MiB、峰值 134 MiB。用稀疏零字节源文件测试边界；接收端执行 SHA-256 校验。不是 Wi-Fi、Android 或完整 Electron 程序内存测量。
- 8 项 Electron 界面回归（含修复语言切换后的焦点恢复）：窗口控制、选择菜单、三语言/持久化、设备身份/备注、文件顺序/方向/状态/滚动、设置、真实文本/批量/粘贴图片/手动连接/自选目录/搜索、取消/PIN 重试与草稿保留。
- `tests/packaged-smoke.cjs`：实际启动打包后的 Windows EXE，验证独立测试数据目录、SQLite 设备改名、繁体默认语言、许可证文件。未接触用户真实数据库。
- `artifacts/transfer-workflow-dark.png` 和 `transfer-workflow-compact.png`：真实 Electron 界面；测试端实际传输了临时文本和图片。正常尺寸及 1000×680 DIP 窗口已检查。
