# LocalSend 协议预览版实现记录

2026-11-21。参考 https://github.com/localsend/protocol 的 v2.2，采用自行实现的适配器，没有复制 LocalSend 客户端代码。

## 可用范围

- 默认网络层切换为 LocalSend；UDP 53317 / 224.0.0.167 发现，HTTPS 服务默认 53317，被占用时选择可用端口并广播实际端口。
- 每个应用数据目录拥有独立的 TLS 证书身份，保存在 locallink-tls.json；名称/IP 不参与身份计算。不能因此认为设备已经配对。
- 实现 register、info、prepare-upload、upload、cancel。发送前接收方明确确认；只接受该会话的源 IP 和随机文件令牌，不做自动接收。
- 界面接入原“附近/收藏/记录”，LocalSend 设备打开聊天式文件时间线；通过原生文件选择框发送单文件。新协议路径暂不支持拖放、粘贴、纯文字或通话，避免误走旧协议。
- HTTPS 自签名证书，发送时将实际证书 SHA-256 与发现指纹比较；这属于发现后的连接一致性校验，不是经用户配对验证的永久信任。发现本身未经认证。
- 接收方只提供 HTTPS。发送到广播为 HTTP 的客户端需额外确认未加密连接。
- 流式读取、发送和写盘；已提供 SHA-256 时必须匹配，同时检查声明长度。元数据上限 1 MiB，每会话不超过 100 个文件、500 MiB；会话十分钟过期，接收最多四会话。当前 UI 一次选择一个文件。
- 默认保存到系统 Downloads/LocalLink/transfer-随机目录/原文件名，避免重名覆盖。拒绝路径穿越、Windows 保留文件名和非法字符。失败删除 partial。
- 发送开始即创建稳定任务 ID，准备、等待确认、传输、失败或送达均更新同一记录；对端 HTTP 200 才写入 delivered。接收完成写入 received，并保留接收开始时间。记录保存于原数据库 locallink.transfers 设置项，提供打开文件和目录。不显示虚构百分比，当前只有等待/传输中及终态。
- 网络 → 高级连接选项可选 Orbit legacy，重启生效。仅启动一种网络层，Orbit 通话/群组数据代码仍保留，LocalSend 设备不显示通话按钮。旧 Orbit userId 历史未自动映射到新证书身份，未删除。
- 新增 selfsigned 5.5.0（MIT）用于本机生成证书；依赖清单已更新。BAT 增加缺依赖检查。

## 验证

`node desktop/tests/localsend-protocol.test.js`：两个独立 HTTPS 实例，2 MiB+1 byte 随机文件逐字节一致；拒收不记送达；错误令牌、错误哈希、证书变更、危险文件名均拒绝。使用临时目录和实际网络流，不是传输 mock。

Windows Electron：LocalSend 实际启动成功，新设备进入专用传输面板；语言及设置回归共 4 个 E2E 通过。截图 localsend-transfer-preview.png 包含注入的 Test LocalSend；当时还观察到局域网设备广播，未据此证明这些设备的具体软件版本或完整互通。

未验证/未实现：与原版 LocalSend Windows/Android 双机收发及 PIN 客户端、复杂防火墙/多网卡/IPv6、500 MiB 峰值内存和慢网长传、断网续传、用户主动取消发送 UI、批量选择、原文件时间戳、文本/图片粘贴、证书到期轮换和密钥变更授权。PIN 401 目前显示失败，不能宣称完整支持所有协议可选能力。接收错误反馈目前为通知；未建持久的失败接收卡片。

此阶段为协议预览版，非全面替换完成或生产安全认证。后续顺序：原版客户端互测 → 接收目录设置/任务进度与取消 → 文本与拖放 → 独立配对授权 → 旧数据映射与 Android。
