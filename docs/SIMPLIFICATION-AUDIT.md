# LocalLink 产品精简与架构审查

日期：2026-11-21。依据本地源码及 Windows Electron 渲染检查；不是完整安全审计。优先规则：用户能否发现设备、选择内容、明确同意接收、可靠传完并找到文件。不能帮助这条路径的功能默认不占据主界面。

## 方向纠正

用户最新要求优先：Orbit 主要提供前端布局与交互基础，LocalLink 是传输工具，目标互通对象为 LocalLink / 原版 LocalSend。此前以 Orbit 网络体系长期保留为默认的规划需要调整。

当前实际仍运行 Orbit UDP/TCP 协议；不能用字符串替换宣称已经兼容 LocalSend。本轮附近提示改为打开 LocalLink，并明确开发版尚不支持 LocalSend。真正互通需完成发现、接收确认、HTTP(S) 传输、错误映射及原版互测后再改成“打开 LocalLink 或 LocalSend”。

## 比界面删除更优先的技术工作

1. **LocalSend 互通主路径（最高优先级）**：统一 device/transfer 接口，适配 LocalSend 发现、prepare/upload/cancel、接收确认、文件 token、错误状态。原 Orbit 传输仅过渡；同一任务只能由一个适配器执行。避免做第二套设备目录和传输 UI。与未修改的 LocalSend Windows/Android 双向测试后才能宣称兼容。
2. **可靠完成状态**：本地保存、连接等待、发送字节、接收方确认、失败分开；100% 字节写出不能直接等于已保存。
3. **完整性**：`network/transfer.js` 新传输 hash 不一致仍保存，是现存缺陷；跨平台 SHA-256 不同不能当成正常。采用失败/隔离路径并覆盖缺 hash、损坏、截断与续传。
4. **内存**：`chat-panel.js` 的 Promise.all(file.arrayBuffer()) 会同时读入所选文件；改为流式读取、背压和有界并发，测量多文件/大文件峰值。
5. **大小限制**：桌面 500 MB 目前主要作为配置出现，未证明发送和接收都强制执行。协议入口、磁盘空间与文件名校验应统一。
6. **保存位置**：当前 BLOB/localPath/temp 多路径并存；优先显式接收目录、冲突命名、打开文件/目录、临时文件清理。清理和导出不能误删历史引用。
7. **身份与授权**：发现、收藏、配对、自动接收分别存储；每台设备独立身份，证书/密钥变化需要重新确认。不要把上游自动 TCP 连接当配对。
8. **协议分工**：LocalSend 作为基本传输互通层；LocalLink 间通话等增强功能独立声明能力。Android 后台与跨网另行验收。

## 建议的设置终态

本设备（名称、类型） / 接收与存储（目录、接收规则、空间） / 外观（主题、缩放） / 通知 / 高级（诊断、历史迁移） / 关于。

删除规则：先确定功能边界和数据处置，再删除入口、状态、事件、实现及无引用素材；不要只藏控件却让外部请求继续运行，也不要为“代码更少”删除校验、错误反馈、键盘操作或版权说明。
