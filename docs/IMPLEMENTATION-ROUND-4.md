# 第四轮：1.0.0 开发版、通讯与便携启动

用户要求保持版本 1.0.0；desktop 包及锁文件已恢复。上一轮 1.1.0 记录和安装包是历史产物，不代表正式发布。目前仍为 Windows 开发版，没有宣称已完成正式发布验收。

## 本轮已落地

- `npm run build:win:portable` 生成 `desktop/dist/portable/LocalLink-1.0.0-Portable.exe`。单文件免安装，启动时解压至临时位置；数据仍在原 userData（默认 orbit-beta），并非数据随 EXE 移动的 U 盘模式。保留 --user-data-dir。未签名。
- 在现有 LocalSend HTTPS 服务上协商 `locallink.messages:1`，不新增第二套发现/连接服务。新版客户端间发送原生文字并在收到明确确认后显示已送达；接收方保存真实文字记录，不落地 TXT。对不声明能力的原版 LocalSend 保留 TXT 兼容路径。
- 原生文字有 64 KiB 边界、拒收、失败、取消和重试。仍是逐次确认；可在配对后主动授权自动接收。没有离线持久队列、消息去重同步或已读回执。网络中断时可能已接收但未获确认，重试可能重复，未声称恰好一次送达。
- 双端配对确认：展示对方名称与 SHA-256 证书指纹。传输服务请求可选 TLS 客户端证书；普通 LocalSend 无客户端证书时仍可手动接收。LocalLink 配对必须提供证书私钥证明，且客户端证书指纹必须与声明身份一致；发送方也验证接收方证书。
- 配对与自动接收分开，配对后默认仍需确认。对话底部盾牌按钮管理配对、自动接收和本机撤销；离线已配对设备仍可撤销本机权限。收藏不授予权限。授权仅对呈现匹配客户端证书的请求有效，证书改变为另一设备身份。撤销是本机授权撤销，不会远程擦除另一端记录。
- 拖入文件夹经过与选择文件夹相同的 ZIP 路径；批量文件和目录共用入口。符号链接拒绝。仍使用 500 MiB 上限，不支持直接目录流/断点续传。
- 数据管理增加“清理已送达的发送缓存”：仅回收 outbox 内、所有引用记录均为已送达的文件。保留失败任务及外部源文件；确认后移到回收站，保留历史并清空可打开路径。不是自动定期清理；无记录孤立缓存及空目录暂不清理。

## 已验证

- communications.test.cjs：三个独立 TLS 客户端，原生文字送达/拒收、真实客户端证书身份、配对、伪造已配对身份被拒、撤销后拒收、文字大小边界。
- 原有 HTTPS 协议/传输任务测试通过。
- 三语与传输界面回归通过；增强工作流检查发送缓存回收不影响源文件，以及配对、默认不自动接收、明确授权与撤销的持久状态。
- portable-smoke.cjs：实际启动单个便携 EXE，连接其调试端口，验证版本 1.0.0、繁体默认、设置改名、隔离 SQLite 写入；结束时仅终止测试启动的进程树。
